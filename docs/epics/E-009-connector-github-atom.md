# E-009: Коннектор GitHub через .atom

## Цель

Релизы и коммиты отслеживаемых репозиториев попадают в `RawItem` без токена и без расхода
квоты REST API.

## Контекст (читать перед началом, по порядку)

1. `packages/connectors/src/rss/index.ts` — образец формы и почти тот же формат: `.atom` —
   это Atom. Разбор переиспользуется, если это не превращается в общую абстракцию ради
   абстракции (см. Границы).
2. `packages/core/src/connector.ts` — контракт коннектора.
3. **Измерено 2026-08-24:** `github.com/<owner>/<repo>/releases.atom` и
   `.../commits/main.atom` отвечают 200 **без аутентификации** и, в отличие от REST,
   не тратят лимит в 60 запросов/час для анонимного клиента. Для проекта, который ходит из
   GitHub Actions с датацентрового IP, это существенная разница.
4. Почему коммиты, а не только релизы: каждый коммит в awesome-репозиторий
   (`awesome-claude-code`, `awesome-mcp-servers`) — это чья-то находка рабочего приёма.
   Релизы дают changelog вендоров, коммиты — практику сообщества; это два разных типа
   ценности из одного коннектора.
5. E-006 снял необходимость править `profiles/schema.ts`. До его мержа эпик не берётся.

## Объём — карта файлов

- `packages/connectors/src/github/index.ts` — коннектор, вид ленты в конфиге
  (`releases` | `commits`).
- `packages/connectors/src/github/index.test.ts`
- `fixtures/github/*.atom.xml` — по фикстуре на каждый вид ленты.
- `packages/connectors/src/registry.ts` — генерируемый.

## Вне объёма

- Правка профилей: список отслеживаемых репозиториев — продуктовое решение темы.
- GitHub REST и GraphQL, `GH_PAT`. Весь смысл эпика — обойтись без них.
- `CHANGELOG.md` через API как источник — отдельный случай с другим форматом.

## Критерии приёмки

- [x] КОГДА коннектор запущен на фикстуре ленты релизов,
      ТО каждый релиз становится `RawItem` с заголовком, ссылкой и датой публикации.
- [x] КОГДА коннектор запущен на фикстуре ленты коммитов,
      ТО merge-коммиты и коммиты ботов отфильтрованы по правилу, заданному конфигом
      источника, а не константой в коде.
- [x] КОГДА в фикстуре переименовано обязательное поле Atom,
      ТО прогон падает с `SourceDriftError`, называющим поле. Показать красным.
- [x] КОГДА источник отдаёт меньше `expectMinItems`,
      ТО `SourceUnavailableError`, прогон продолжается без него, факт попадает в отчёт.
- [x] КОГДА в конфиге указан несуществующий репозиторий и живой прогон получает 404,
      ТО поднимается `SourceUnavailableError` с именем репозитория, а не общая сетевая
      ошибка.
- [x] КОГДА `pnpm test` запущен,
      ТО ни один тест не поднимает `NetworkAccessInTestError` — фикстура покрывает всё,
      что коннектору нужно от источника.

## Верификация

```bash

```

## Границы

**Не выделяй общий Atom-коннектор, пока их не станет три.** Соблазн обобщить RSS и GitHub в
один параметризуемый коннектор появится сразу. Два случая — не закономерность, а общая
абстракция, построенная на двух примерах, обычно ломается на третьем. Переиспользовать
функцию разбора — да; заводить общий коннектор — нет.

**Условный GET обязателен.** `.atom` отдаёт `ETag`; лента, опрашиваемая трижды в день без
`If-None-Match`, — это вежливость, которая ничего не стоит, и она уже поддержана
`HttpClient`.

## План реализации

1. `fixtures/github/widget-cli-releases.atom.xml` и `fixtures/github/widget-cli-commits.atom.xml` —
   рукописные, по форме, которую реально отдаёт GitHub (пространства имён Atom + media,
   `tag:github.com,2008:` в `<id>`, `<updated>` без `<published>`, `<content type="html">`
   с `<pre style='white-space:pre-wrap;'>` у коммитов). Репозиторий вымышленный, и это
   сказано в шапке каждого файла: фикстура — доказательство ФОРМЫ, а не запись чьей-то
   ленты.
2. `packages/connectors/src/github/index.ts`, `kind: "github"` (директория `github`).
   Дефис в `kind` запрещён генератором — `KIND_PATTERN = /^[a-z0-9]+$/`.
3. Конфиг: `owner`/`repo`/`feed` (`releases` | `commits`)/`branch`/`sourceName` плюс
   `excludeTitlePatterns` и `excludeAuthorPatterns` — массивы regex-строк, по умолчанию
   пустые. Правило отсева merge-коммитов и ботов задаётся источником; в коде нет ни одной
   константы, называющей «merge» или «bot».
4. URL ленты строится из конфига: `…/releases.atom` и `…/commits/<branch>.atom`. Никакого
   REST, никакого токена. `owner`/`repo`/`branch` валидируются charset'ом на границе —
   иначе конфиг умеет дописать в URL произвольный путь или query.
5. Разбор: те же три помощника, что в RSS (`asArray`/`text`/`linkOf`), скопированы, а не
   вынесены — см. `## Границы` и `## Заметки`.
6. Drift: `parseOrDrift` на каждый entry; `id`/`url`/`title`/`updated` обязательны всегда,
   `author` — дополнительно обязателен для `feed: "commits"`, потому что именно по нему
   работает отсев ботов, и молча пропавший `<author>` означал бы молча выключенный фильтр.
7. 404: `SourceUnavailableError`, называющий `owner/repo`, вид ленты и — для `commits` —
   ветку. Ветка-опечатка (`main` там, где `master`) даёт ровно тот же 404, что и
   несуществующий репозиторий, и без имени в сообщении это неотличимо.
8. Тесты — на фикстурах, без сети; drift показан красным на ослабленном коннекторе
   (транскрипт в отчёте), `expectMinItems` — через `assertPlausibleYield`.
9. `pnpm gen:connectors` перегенерирует `registry.ts`. `packages/connectors/src/index.ts`
   не трогается: у его ре-экспортов нет потребителей, и E-006a предлагает их снять.

### Что решено внутри карты, и что было отвергнуто (исполнитель, 2026-08-29)

**Помощники разбора скопированы из RSS, а не вынесены.** `asArray`, `text` и `linkOf` в
`github/index.ts` — копия трёх функций из `rss/index.ts`. Вынести их в общий модуль или
экспортировать из RSS означало бы править файл вне карты (`packages/connectors/src/rss/index.ts`
или новый `packages/connectors/src/atom.ts`), а `## Границы` запрещает общий Atom-коннектор
до третьего случая. Выбран самый консервативный вариант внутри карты — дублирование, 30
строк. Триггер для вынесения: **третий** потребитель Atom; тогда это отдельный эпик с картой,
включающей оба существующих коннектора.

**`packages/connectors/src/index.ts` не тронут.** Пер-коннекторных ре-экспортов для github
не добавлено: у экспортов RSS нет ни одного потребителя за пределами пакета (измерено в
E-006), а E-006a предлагает их снять. Добавить свои две строки значило бы закрепить ровно тот
хотспот, который E-006a закрывает, и создать конфликт с параллельным E-008.

**`expectMinItems: 1` — известный ложноположительный случай.** Политика живёт на
**коннекторе**, а правдоподобный минимум — свойство **источника**: репозиторий, честно не
выпустивший релиз за окно, отдаст ноль и будет помечен degraded на каждом прогоне. Отвергнуто:
`expectMinItems: 0` (это ровно тот тихий отказ, который запрещает DoD #4) и различение
«лента пуста» / «всё старше окна» внутри коннектора (для репозитория без релизов лента
действительно пуста, и это не дрейф). Правка требует пер-источникового переопределения в
`profiles/schema.ts` и `ConnectorPolicy` — обе вне карты. Формулировка для владельца — ниже,
в retrospective.

**Дата релиза — из `<updated>`.** `releases.atom` не отдаёт `<published>` вообще; `<updated>`
там единственная отметка времени. Для релиза это момент публикации, **если** заметки потом не
редактировали, — отредактированный релиз получит дату правки. Проверено на фикстуре
`fixtures/github/widget-cli-releases.atom.xml`, где `<published>` отсутствует у всех пяти
записей; это же и причина, по которой `updated` объявлен обязательным полем схемы.

**Фикстуры рукописные, и это сказано в них самих.** Ключ `_handAuthored` — соглашение для
JSON-фикстур LLM, в XML его положить некуда, поэтому происхождение записано комментарием в
первых строках каждого файла: репозиторий `acme-labs/widget-cli` вымышлен, доказательством
является **форма** ленты, а не чья-либо реальная история релизов.

**Профили не тронуты** (прямое указание в `## Вне объёма`): ни один профиль пока не объявляет
источник с `kind: "github"`, коннектор приезжает неиспользуемым. Список отслеживаемых
репозиториев — продуктовое решение темы.

**Зафилен стаб E-009a** — `docs/epics/E-009a-http-status-reaches-the-connector.md`.
`LiveHttpClient` на 4xx бросает ошибку и никогда не возвращает `HttpResponse.status`, поэтому
`looksLike404` в этом коннекторе сопоставляет подстроку `404` с текстом чужого сообщения.
Работает и покрыто тестом, но по форме неверно: правка формулировки в `apps/pipeline/src/http.ts`
выключит именование репозитория молча.

### Rules retrospective (исполнитель)

- **Сработало:** DoD #7, «сломай починку двумя разными способами». Мутация «правило отсева
  зашито константой в коннектор» оставила **зелёным** главный тест
  «drops merge commits and bot commits by the source's rules» — потому что зашитая константа
  совпадала с настроенным правилом. Без этой проверки уехал бы набор тестов, не отличающий
  конфиг от константы, то есть слепой ровно к тому нарушению инварианта, ради которого
  критерий #2 написан. Пришлось добавить два теста: «7 записей без правил» и «правило, не
  имеющее отношения к merge и ботам».
- **Мешало или молчало:** `.claude/rules/pipeline.md` § Коннектор объявляет `expectMinItems`
  одной из трёх обязательных вещей и молчит о том, что порог живёт на **коннекторе**, а
  правдоподобие — на **источнике**. Для GitHub это не теория: релизный репозиторий с тихой
  неделей отдаёт ноль легально и будет помечен degraded каждый прогон. Правило не даёт
  исполнителю выхода: занизить порог оно запрещает, переопределить — нечем.
  Второе, мельче: § Фикстуры требует ключ `_handAuthored` от рукописной заглушки, но ключ
  существует только для JSON-фикстур LLM; для рукописной XML-фикстуры источника соглашения
  нет, и оно изобретается заново каждым коннектором.
- **Предложение:**
  1. В `.claude/rules/pipeline.md`, § Коннектор, после пункта 3 добавить: «`expectMinItems`
     — порог **коннектора**, а правдоподобный минимум — свойство **источника**. Если для
     какого-то источника ноль за окно легален (репозиторий без релизов, сезонная лента),
     это не повод занижать порог до нуля: заводи эпик на пер-источниковое переопределение и
     до его мержа терпи запись в degraded. Тихо принятый ноль — тот самый худший режим
     отказа, ради которого поле существует.»
  2. Там же, § Фикстуры, дополнить: «Ключ `_handAuthored` — соглашение JSON-фикстур LLM. У
     рукописной фикстуры источника в XML или HTML его положить некуда, поэтому её
     происхождение пишется комментарием в первых строках файла: дата, факт «не записано, а
     написано руками» и что именно фикстура доказывает — форму ответа, а не чьи-либо
     реальные данные.»

### После мержа main в ветку (исполнитель, 2026-08-29)

E-006a успел смержиться в main, пока эпик был в работе, и снял пер-коннекторные
ре-экспорты из `packages/connectors/src/index.ts` целиком. Решение «бочку не трогать»,
принятое выше по догадке, теперь подкреплено гейтом: `packages/connectors/src/index.test.ts`
на main падает, если экспорт или импорт в бочке резолвится не в `./registry.js`. Коннектор
`github` не добавил туда ни строки, и после мержа main ветка зелёная: `pnpm verify` —
142 теста, 183 проверки хук-батареи, `registry.ts` актуален. Frontmatter в этом файле
выровнен по main (`status: todo`), как требует § «При конфликте мержа в эпик-файле».
