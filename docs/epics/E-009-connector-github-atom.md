# E-009: Коннектор GitHub через .atom

## Цель

Релизы и коммиты отслеживаемых репозиториев попадают в `RawItem` без токена и без расхода
квоты REST API.

## Контекст (читать перед началом, по порядку)

1. `packages/connectors/src/rss/index.ts` — образец формы и почти тот же формат: `.atom` —
   это Atom. Разбор переиспользуется, если это не превращается в общую абстракцию ради
   абстракции (см. Границы).
2. `packages/core/src/connector.ts` — контракт коннектора.
3. **Измерено 2026-08-24:** `github.com/<owner>/<repo>/releases.atom` и
   `.../commits/main.atom` отвечают 200 **без аутентификации** и, в отличие от REST,
   не тратят лимит в 60 запросов/час для анонимного клиента. Для проекта, который ходит из
   GitHub Actions с датацентрового IP, это существенная разница.
4. Почему коммиты, а не только релизы: каждый коммит в awesome-репозиторий
   (`awesome-claude-code`, `awesome-mcp-servers`) — это чья-то находка рабочего приёма.
   Релизы дают changelog вендоров, коммиты — практику сообщества; это два разных типа
   ценности из одного коннектора.
5. E-006 снял необходимость править `profiles/schema.ts`. До его мержа эпик не берётся.

## Объём — карта файлов

- `packages/connectors/src/github/index.ts` — коннектор, вид ленты в конфиге
  (`releases` | `commits`).
- `packages/connectors/src/github/index.test.ts`
- `fixtures/github/*.atom.xml` — по фикстуре на каждый вид ленты.
- `packages/connectors/src/registry.ts` — генерируемый.

## Вне объёма

- Правка профилей: список отслеживаемых репозиториев — продуктовое решение темы.
- GitHub REST и GraphQL, `GH_PAT`. Весь смысл эпика — обойтись без них.
- `CHANGELOG.md` через API как источник — отдельный случай с другим форматом.

## Критерии приёмки

- [ ] КОГДА коннектор запущен на фикстуре ленты релизов,
      ТО каждый релиз становится `RawItem` с заголовком, ссылкой и датой публикации.
- [ ] КОГДА коннектор запущен на фикстуре ленты коммитов,
      ТО merge-коммиты и коммиты ботов отфильтрованы по правилу, заданному конфигом
      источника, а не константой в коде.
- [ ] КОГДА в фикстуре переименовано обязательное поле Atom,
      ТО прогон падает с `SourceDriftError`, называющим поле. Показать красным.
- [ ] КОГДА источник отдаёт меньше `expectMinItems`,
      ТО `SourceUnavailableError`, прогон продолжается без него, факт попадает в отчёт.
- [ ] КОГДА в конфиге указан несуществующий репозиторий и живой прогон получает 404,
      ТО поднимается `SourceUnavailableError` с именем репозитория, а не общая сетевая
      ошибка.
- [ ] КОГДА `pnpm test` запущен,
      ТО ни один тест не поднимает `NetworkAccessInTestError` — фикстура покрывает всё,
      что коннектору нужно от источника.

## Границы

**Не выделяй общий Atom-коннектор, пока их не станет три.** Соблазн обобщить RSS и GitHub в
один параметризуемый коннектор появится сразу. Два случая — не закономерность, а общая
абстракция, построенная на двух примерах, обычно ломается на третьем. Переиспользовать
функцию разбора — да; заводить общий коннектор — нет.

**Условный GET обязателен.** `.atom` отдаёт `ETag`; лента, опрашиваемая трижды в день без
`If-None-Match`, — это вежливость, которая ничего не стоит, и она уже поддержана
`HttpClient`.
