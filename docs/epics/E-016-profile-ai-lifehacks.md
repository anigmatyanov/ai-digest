# E-016: Профиль основной темы

## Цель

Пайплайн, запущенный на `profiles/ai-lifehacks.ts`, собирает выпуск из настоящих источников —
без единой правки в `packages/`.

## Контекст (читать перед началом, по порядку)

1. **Почему сейчас.** В репозитории один профиль — `_test.ts`, и он смотрит в записанную
   фикстуру. Три коннектора (`rss`, `hn`, `github`) смержены и не используются ни одной
   темой. Продукт умеет всё, кроме того, ради чего он написан.
2. `profiles/_test.ts` — образец формы и единственный профиль, против которого агенты гоняют
   пайплайн. Он остаётся офлайновым и не меняется.
3. `profiles/schema.ts` — форма профиля. Схема **не меняется**: если для источника нужно поле,
   которого нет, это дефект коннектора или отдельный эпик, а не правка схемы здесь.
4. Стартовый набор источников назван в утверждённом плане (раздел «Стартовый набор
   источников») и отобран по одному признаку — плотность практических приёмов на единицу
   шума. Из него берётся только то, для чего уже есть коннектор.
5. `.claude/rules/pipeline.md` § Профиль: профиль не импортирует ничего, кроме `schema.ts`.
   Захотелось `if` — это стадия, а не конфиг.

## Объём — карта файлов

- `profiles/ai-lifehacks.ts` — новый.
- `profiles/package.json` — если профиль требует регистрации (проверить, как собирается
  `profiles/dist`).
- `docs/setup.md` — если для живого прогона владельцу нужно что-то завести.

## Вне объёма

- `profiles/schema.ts`. Любая нехватка поля — отдельный эпик.
- Новые коннекторы. Берём только `rss`, `hn`, `github`; источники без коннектора (Anthropic
  engineering, Bluesky, `t.me/s/`, YouTube) ждут своих эпиков.
- `profiles/_test.ts`. Он офлайновый и остаётся таким.
- Живой прогон и публикация. Профиль пишется, не запускается.
- Фикстуры для этих источников. Живой профиль ходит в сеть по расписанию; офлайн-гейт — это
  `_test.ts`.

## Критерии приёмки

- [x] КОГДА запущен `pnpm profile:validate`,
      ТО `ai-lifehacks` проходит валидацию наравне с `_test`, и в выводе видно число
      включённых источников.
- [x] КОГДА в профиле указан источник с `kind`, для которого нет коннектора,
      ТО валидация падает с именем вида — то есть профиль не может сослаться на то, чего нет.
- [x] КОГДА `pnpm verify` запущен,
      ТО он зелёный, и ни один тест не ходит в сеть из-за нового профиля.
- [x] КОГДА профиль сравнивают с `_test.ts`,
      ТО видно, что тематическое (что считать приёмом, стиль, исключения) живёт здесь, а не
      в `packages/` — `git diff` по `packages/` относительно начала ветки пуст.
- [ ] КОГДА источник в профиле выключен (`enabled: false`),
      ТО причина записана рядом комментарием — выключенный без объяснения источник через
      месяц неотличим от забытого.

## Верификация

```bash
pnpm profile:validate
pnpm verify
pnpm build:proof
```

## Границы

**Профиль — это продуктовые решения, а не конфиг.** Пороги, квоты по типам карточек, что
считать приёмом и чего не берём — за это отвечает владелец темы, и поэтому эпик `paired`.
Скопировать значения из `_test.ts` «чтобы прошло» — это поставить тестовые пороги в прод.

**`touches_output: true`.** Профиль определяет всё, что читатель увидит. В батче он один.

**Ни одного источника без коннектора.** Соблазн вписать `anthropic.com/engineering` заранее,
«чтобы не забыть», кончается профилем, который не проходит валидацию. Место для памяти —
`## Заметки`, а не `sources`.

### 2026-08-30 — профиль написан, и он вскрыл дефект схемы

Десять источников на трёх коннекторах: три блога практиков, два вендорских changelog'а, HN с
порогом 100, Lobsters и два awesome-репозитория по коммитам. Все включены, выключенных нет,
поэтому пятый критерий неприменим — отмечать нечего.

**Найдено: дефолт в конфиге коннектора ничего не даёт автору профиля.** `Profile` выводится
через `z.infer`, то есть из выходного типа схемы, где дефолты уже применены и обязательны.
Источник с лентой релизов GitHub вынужден написать `branch: "main"`, который для релизов не
значит ничего, плюс два пустых массива; HN-источник — `tags: "story"`. Профиль в результате
заявляет то, чего не выбирал. Зафилено как **E-017**; здесь поля выписаны явно с комментарием
на месте, а не обойдены.

Пороги — продуктовые решения, а не копия из `_test.ts`: окно 10 дней вместо 3650 (тестовый
профиль намеренно широк, чтобы golden не зависел от даты прогона), `minBodyChars` 600 вместо
200, `cardsPerIssue` 5–10 вместо 1–4, `maxPerSource` 2 вместо 4, `compose` на Opus вместо
Sonnet, бюджет $4 на прогон при измеренном baseline $0.046 за шесть вызовов extract.

`delivery` пуст намеренно: канала в профиле не будет, пока E-010 не поставит публикацию.
Профиль, называющий канал раньше, чем существует код доставки, врёт о том, что сделает прогон.
