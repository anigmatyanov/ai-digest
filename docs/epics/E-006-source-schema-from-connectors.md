# E-006: Схема конфига источника собирается из коннекторов

## Цель

Добавление коннектора не требует правки ни одного общего файла: вариант конфига источника
объявляется в директории коннектора и попадает в схему профиля кодогенерацией.

## Контекст (читать перед началом, по порядку)

1. **Дефект, ради которого эпик существует.** `profiles/schema.ts` содержит
   `SourceSchema = z.discriminatedUnion("kind", [RssSourceSchema])`. Каждый новый источник
   обязан дописать сюда свой вариант, то есть тронуть файл под меткой `profile-schema`.
   Значит два агента, добавляющих коннекторы, сериализуются — при том что всё остальное для
   параллельной работы уже сделано.
2. `packages/connectors/src/registry.ts` — как выглядит цель. Он **генерируется**
   `scripts/gen-connectors.mjs`, актуальность проверяет `pnpm verify` через `--check`, и
   именно поэтому реестра коннекторов нет в serialize-списке. Схема источника должна
   получить то же свойство.
3. `packages/core/src/connector.ts` — у коннектора **уже есть** `configSchema`. Информация,
   которую сейчас дублирует `profiles/schema.ts`, в коннекторе присутствует; задача не
   «придумать, где её взять», а перестать дублировать.
4. `apps/pipeline/src/ingest.ts` — доказательство, что остальной путь уже агностичен:
   `getConnector(source.kind)` и `config: Record<string, unknown>`. Ниже профиля вид
   источника нигде не зашит.
5. CLAUDE.md § Правила параллельной работы, пункт 5 и
   [.claude/rules/backlog.md](../../.claude/rules/backlog.md) § serialize-реестр —
   формулировка «устранённый хотспот лучше запертого». Этот эпик — её применение.

## Объём — карта файлов

- `profiles/schema.ts` — общая часть записи об источнике (`key`, `kind`, `weight`,
  `enabled`, `fixture`) и сборка союза из вкладов коннекторов.
- `scripts/gen-connectors.mjs` — генерация вкладов наряду с реестром.
- `packages/connectors/src/*/index.ts` — коннектор объявляет свой вариант.
- `packages/connectors/src/registry.ts` — генерируемый файл, руками не править.
- `profiles/_test.ts` — если изменится форма записи источника.
- тесты рядом с затронутым кодом.

## Вне объёма

- Новые коннекторы. Этот эпик не добавляет источников — он снимает блокировку с тех, кто их
  добавит (E-008, E-009).
- Схема профиля вне блока источников: `prefilter`, `selection`, `llm`, `delivery`.
- Загрузчик профиля и `pnpm profile:validate` — меняются только если сломались.

## Критерии приёмки

- [ ] КОГДА в `packages/connectors/src/` появляется новая директория с коннектором и
      запускается `pnpm gen:connectors`, ТО его конфиг проходит валидацию профиля **без
      единой правки в `profiles/schema.ts`**.
- [ ] КОГДА в профиле указан `kind`, которому не соответствует ни один коннектор,
      ТО ошибка называет неизвестный вид и перечисляет известные — на этапе разбора
      профиля, а не при обращении к сети.
- [ ] КОГДА в конфиге источника опечатка в имени поля (`chanel` вместо `channel`),
      ТО валидация профиля падает с указанием поля — то есть свойство, ради которого схема
      писалась на TypeScript, а не на YAML, сохранено.
- [ ] КОГДА коннектор добавлен, но `pnpm gen:connectors` не запущен,
      ТО `pnpm verify` краснеет и говорит, какую команду выполнить.
- [ ] КОГДА два коннектора объявляют один и тот же `kind`,
      ТО генерация падает с именами обеих директорий, а не выбирает одну молча.
- [ ] КОГДА ветка добавляет коннектор-пустышку и запускает `pnpm gen:connectors`,
      ТО `git diff --name-only main` не содержит `profiles/schema.ts` — цель эпика
      измерена, а не заявлена. Пустышка в PR не остаётся.

## Верификация

```bash
pnpm gen:connectors
pnpm profile:validate
pnpm verify
pnpm digest:run --profile profiles/dist/_test.js --fixtures --dry-run
```

## Границы

**Автокомплит конфига — то, ради чего схема на TypeScript.** Решение, собирающее союз через
`z.record(z.string(), z.unknown())`, формально «работает» и уничтожает единственную причину
не писать профили в YAML. Если типизацию сохранить не удаётся — это находка для владельца, а
не повод тихо ослабить схему.

**Цикла зависимостей быть не должно.** Сейчас `connectors → core`. Если `profiles → connectors`
создаёт цикл — генерировать отдельный модуль вкладов, а не тянуть пакет целиком.

**Профиль по-прежнему не импортирует ничего, кроме `profiles/schema.ts`.** Это правило про
файлы профилей; на сам `schema.ts` оно не распространяется, но проверить, что оно не поехало,
обязательно.
