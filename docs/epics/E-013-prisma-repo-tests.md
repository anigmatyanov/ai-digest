# E-013: Тесты на PrismaRepo

## Цель

Подмена уникального ключа в любом upsert'е `PrismaRepo` краснит `pnpm test`, а не
обнаруживается через месяц удвоившимся выпуском.

## Контекст (читать перед началом, по порядку)

1. **Дефект, ради которого эпик существует.** `packages/db/src/prisma-repo.ts` — 358 строк,
   несущих всю идемпотентность продукта, и **ни одного теста**. Единственное доказательство —
   транскрипт живого прогона в `## Заметки` эпика E-007. Ревьюер сформулировал точно: замена
   `where: { sourceId_externalId: … }` на `where: { id }` пройдёт `pnpm verify` зелёной.
2. `.claude/rules/testing.md` § «Что тестом не ловится»: «Живой прогон — доказательство, но
   не гейт: он не оставляет в репозитории ничего, что покраснеет завтра». E-007 закрыт именно
   в этом состоянии, осознанно и с записью в заметках. Этот эпик закрывает разрыв.
3. `packages/db/src/client.test.ts` — образец теста в этом пакете, не требующего БД.
4. `test/setup/no-network.ts` подменяет `fetch`. **Важно:** `PrismaNeon` ходит через
   WebSocket, а не через `fetch`, поэтому существующий сетевой гард этот путь не видит —
   найдено тем же ревью. Тест, случайно открывший соединение, не будет пойман.
5. E-007 `## Заметки`, запись от 2026-08-29 про ревью — там перечислено, что именно
   доказано живьём и что осталось без гейта.

## Объём — карта файлов

- `packages/db/src/prisma-repo.test.ts` — новый.
- `packages/db/src/prisma-repo.ts` — только если контур не тестируется без правки формы
  (например, клиент придётся принимать через параметр).
- `packages/db/package.json` — если понадобится тестовая зависимость.
- `test/setup/no-network.ts` — если решение закрыть WebSocket-путь окажется в этом эпике.

## Вне объёма

- Тесты стадий и раннера. Здесь только репозиторий.
- Векторные запросы: их пока нет.
- E-011 (продолжение прогона по статусу). Он будет звать `listCandidates`, но это его работа.

## Критерии приёмки

- [ ] КОГДА в любом `upsert` уникальный ключ заменён на `where: { id }`,
      ТО `pnpm test` краснеет, называя метод.
- [ ] КОГДА транзакция вокруг переписывания join-таблицы разбита на два отдельных запроса,
      ТО тест краснеет — свойство «между delete и create нет окна» проверяется, а не
      подразумевается.
- [ ] КОГДА `putRawItems` перестаёт возвращать персистентный id,
      ТО тест краснеет: на этом держатся все ссылки внутри прогона.
- [ ] КОГДА `pnpm test` запущен без `DATABASE_URL` и без сети,
      ТО он зелёный и не открывает ни одного соединения — включая WebSocket, который
      нынешний сетевой гард не видит.
- [ ] КОГДА тест прогоняется на коде до починки соответствующего дефекта,
      ТО он красный; транскрипт в отчёте по каждому кейсу.

## Верификация

```bash
pnpm verify
pnpm typecheck
```

## Границы

**Не тестируй Prisma.** Проверять надо форму вызова — какой ключ в `where`, что попало в
`create` против `update`, что вернулось наружу, — а не то, что Postgres соблюдает уникальный
индекс. Тест, поднимающий настоящую базу, здесь дороже пользы и уводит `pnpm test` в сеть.

**Фейковый клиент — не мок ради мока.** Если для проверки формы вызова приходится описывать
половину Prisma Client, это сигнал, что контур стоит вынести в чистую функцию, строящую
аргументы upsert'а, и тестировать её.

**Сетевой гард не покрывает WebSocket.** Если закрывать это здесь — сказать в отчёте, что
изменилось для всех остальных тестов; если не здесь — зафилить стабом.
