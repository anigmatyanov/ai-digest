# E-012a: exemption, который можно приделать префиксом, — это байпас

## Цель

Ни один `exit 0` в `live-effects-guard.sh` не срабатывает на команде, у которой опасный
эффект стоит после безобидного первого сегмента.

## Контекст (читать перед началом, по порядку)

1. Урок уже записан в самом файле — рядом с carve-out'ом для `pnpm`: «An exemption that can
   be prefixed onto an arbitrary command is not an exemption, it is a bypass». Тогда его
   применили к одному carve-out'у из шести. Остальные проверялись только на своей форме.
2. `.claude/hooks/live-effects-guard.sh`, фаза 2. Три места, найденные при работе над E-012
   и **не** правленные там, потому что лежат вне секции carve-out'а из карты файлов E-012:

   - read-only carve-out якорится на начало строки: `^[[:space:]]*(cat|less|head|…|jq)`.
     Поэтому `cat README.md && <опасное>` выходит с 0.
   - `case "$cmd" in *"--dry-run"*|*"--fixtures"*)` матчит подстроку в любом месте, а внутри
     проверяет только флаги публикации. Поэтому `pnpm digest:run --fixtures --dry-run &&
     vercel deploy --prod` выходит с 0 — при том, что `pnpm add zod && vercel deploy --prod`
     заблокирован и запинен в батарее.
   - `--help`/`-h`/`help` матчится в любом месте команды, а не только как флаг первого
     сегмента. `<опасное> ; echo --help` выходит с 0.

3. Все три — один и тот же дефект формы: exemption отвечает на вопрос «есть ли в тексте
   безопасная форма?», тогда как правильный вопрос — «безопасны ли ВСЕ сегменты?».
4. Прецедент правильной формы — в том же файле: carve-out `gh api` и carve-out `neonctl
   branches delete` (E-012) перечисляют дисквалификаторы и снимаются целиком, если в команде
   найдена мутирующая форма.
5. `test/hooks/run.sh` — батарея. Кейсы `bypass attempt: pnpm install && live run` и
   `gh: read prefixed onto an effect` — образец того, как такой кейс формулируется.

## Объём — карта файлов

- `.claude/hooks/live-effects-guard.sh` — три exemption'а фазы 2.
- `test/hooks/run.sh` — кейсы.

## Вне объёма

- Полноценный парсер оболочки. Достаточно разбиения по `;`/`&&`/`||`/`|` и требования,
  чтобы exemption распространялся на команду целиком, а не на факт вхождения подстроки.
- Формы, уже перечисленные в § NAMED LIMITS хука (`eval`, `bash -c`, `xargs`).
- Carve-out `neonctl branches delete` из E-012 — он уже проверяет состояние.

## Критерии приёмки

- [ ] КОГДА команда начинается с read-only глагола, но содержит опасный эффект после
      `&&`/`;`/`|`, ТО она отклоняется.
- [ ] КОГДА команда содержит `--dry-run` или `--fixtures`, но опасный эффект стоит в
      отдельном сегменте, ТО она отклоняется.
- [ ] КОГДА `--help` стоит не в том сегменте, где опасный глагол, ТО команда отклоняется.
- [ ] КОГДА команда состоит только из безопасного сегмента (`cat x`, `neonctl roles --help`,
      санкционированный dry-run), ТО она по-прежнему проходит — все существующие `expect 0`
      в блоке live-effects остаются зелёными.
- [ ] КОГДА новые кейсы прогоняются на коде до починки, ТО они краснеют, а существующие
      остаются зелёными; оба транскрипта — в отчёте.

## Верификация

```bash
bash test/hooks/run.sh
pnpm verify
```

## Границы

**Никогда:** ослаблять существующие `expect 0` ради прохождения новых кейсов. Дешёвый
неверный способ закрыть этот эпик — сделать exemption'ы строже так, что `neonctl me | head`
и `zsh -lc '…'` начнут блокироваться. Ложный блок на инспекционной команде — это то, из-за
чего гард выключают, и он уже трижды случался в этом файле.

**Спросить заранее:** любое изменение формы deny-сообщений (их читает агент, а не человек),
любое расширение за пределы фазы 2.
