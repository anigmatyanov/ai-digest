# E-014: Отставший lockfile не читается как несмерженная работа

## Цель

Ветка, чья работа целиком на main, удаляется без вмешательства человека — даже если общий
сгенерированный файл на main успел уехать дальше.

## Контекст (читать перед началом, по порядку)

1. **Дефект, ради которого эпик существует.** 2026-08-29, уборка после мержа E-006:
   `git branch -D agent/e-006-source-schema-codegen` отклонён с «still holds work that main
   does not have», единственный названный файл — `pnpm-lock.yaml`. Дифф: 79 вставок против
   1451 удаления, то есть **на main файл больше**, а не меньше: туда успел смержиться E-007
   со своими зависимостями Prisma. Вклад самой ветки (ребро `profiles → connectors`) на main
   присутствует — проверено грепом. Ветка осталась висеть ссылкой, worktree и слот убраны
   вручную.
2. `.claude/hooks/git-branch-delete-guard.sh`, секция NAMED LIMITS. Правило: каждый файл,
   изменённый веткой от merge-base, обязан лежать на main с тем же содержимым либо когда-то
   лежать. Для сгенерированного файла, который на main пересобран поверх более широкого
   набора зависимостей, это условие не выполняется никогда.
3. Там же записано исключение для `docs/epics/`. Оно сделано ровно по этой логике — «ветка,
   корректно закрытая, отличается ровно одним файлом» — но список исключений оказался
   неполным.
4. `.claude/rules/backlog.md` § «Удаление ветки — автономное действие»: смысл гарда в том,
   что решение принимается по проверяемому признаку, а не по суждению. Каждый ложный отказ
   возвращает суждение человеку и тем самым обнуляет смысл.

## Объём — карта файлов

- `.claude/hooks/git-branch-delete-guard.sh`
- `test/hooks/run.sh`

## Вне объёма

- Удаление удалённой ветки (`git push origin --delete`). Остаётся запрещённым.
- Удаление по маске и через `xargs` — гард отказывает намеренно, это остаётся.
- Ветки, основанные не на `main`. Тоже намеренно.

## Критерии приёмки

- [ ] КОГДА ветка отличается от main только `pnpm-lock.yaml`, и вклад ветки в него на main
      присутствует, ТО удаление проходит.
- [ ] КОГДА ветка отличается от main файлом с исходным кодом,
      ТО удаление по-прежнему отклоняется с именем файла.
- [ ] КОГДА ветка отличается `pnpm-lock.yaml`, в котором есть запись, отсутствующая на main,
      ТО удаление отклоняется — «сгенерированный» не значит «неважный».
- [ ] КОГДА новые кейсы прогоняются на коде до починки,
      ТО первый краснеет, а второй и третий остаются зелёными.

## Верификация

```bash
bash test/hooks/run.sh
pnpm verify
```

## Границы

**«Сгенерированный файл» — не «файл, который можно игнорировать».** Ослабление до «lockfile
не считается» превращает гард в проверку, которую обходит любая ветка, спрятавшая правку в
lock. Признак должен быть содержательным: каждая запись, добавленная веткой, присутствует на
main. Разница «на main больше» — это норма, разница «на ветке есть чего нет на main» — нет.

**Не расширяй список исключений именами файлов.** `docs/epics/` попал туда по механике
процесса, а не потому что «доки неважны». Второе исключение по той же логике нужно
обосновать так же явно, иначе список начнёт расти по привычке.

## Заметки (append-only)

**2026-08-29.** Ветка `agent/e-006-source-schema-codegen` осталась неудалённой из-за этого
дефекта. Её worktree, слот и ветка Neon убраны; висит только git-ссылка. Удалить её —
первое, что стоит сделать после починки, и заодно это живая проверка первого критерия.

**2026-08-29, второй независимый случай.** После мержа E-009 удаление
`agent/e-009-github-atom-connector` отклонено с тем же диагнозом, но уже на другом
генерируемом файле: `packages/connectors/src/registry.ts`. На main в нём три коннектора
(`github`, `hn`, `rss`), на ветке два — E-008 смержился между делом. Вклад ветки на main
присутствует целиком.

Два случая на двух разных генерируемых файлах за один вечер — значит, дело не в
`pnpm-lock.yaml`, а в том, что признак «тот же байт-в-байт» неприменим к файлу, который
пересобирается из более широкого набора входов. Критерий №1 стоит читать шире, чем
lockfile: он про любой генерируемый артефакт.

Ссылка `agent/e-009-github-atom-connector` тоже осталась висеть; её worktree, слот и ветка
Neon сняты.
