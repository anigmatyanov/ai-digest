# E-017: Дефолты конфига перестают быть декоративными

## Цель

Профиль указывает только те поля конфига источника, которые он действительно выбирает;
остальные приходят из дефолтов коннектора и не пишутся вручную.

## Контекст (читать перед началом, по порядку)

1. **Дефект, найденный при написании первого настоящего профиля (E-016).** `Profile`
   выводится через `z.infer`, то есть из **выходного** типа схемы, где дефолты уже применены
   и потому обязательны. Следствие: каждое поле с `.default()` в конфиге коннектора автор
   профиля обязан написать руками. Измерено на `profiles/ai-lifehacks.ts`: источник с лентой
   релизов GitHub вынужден указать `branch: "main"`, **который для релизов не значит ничего**,
   плюс два пустых массива исключений; HN-источник вынужден указать `tags: "story"`.
2. `profiles/schema.ts` — `Profile = z.infer<typeof ProfileSchema>`. Смена на `z.input`
   выглядит очевидным ходом и **не работает**: `ConnectorDefinition.configSchema` объявлен
   как `z.ZodType<TConfig>`, а у zod 4 это `ZodType<Output, Input = unknown>`, поэтому вход
   схлопнется в `unknown`. Это уже установлено ревью E-006 и записано там же как ловушка.
3. `packages/core/src/connector.ts` — `configSchema: z.ZodType<TConfig>`. Здесь теряется
   входной тип, и починка почти наверняка начинается отсюда.
4. `profiles/schema.ts`, `_sourceConfigStaysTyped` и `_sourceKindStaysLiteral` — compile-time
   стражи, которые обязаны остаться живыми после правки. Один из них специально ловит
   вырождение конфига в `unknown`, то есть ровно тот способ «починить», который делает хуже.
5. DoD #9: меняется схема профиля — все профили обновляются и валидируются в том же PR.
   Их сейчас два.

## Объём — карта файлов

- `packages/core/src/connector.ts` — сохранить входной тип конфига.
- `profiles/schema.ts` — тип, который видит автор профиля.
- `profiles/schema.test.ts`
- `profiles/ai-lifehacks.ts`, `profiles/_test.ts` — снять поля, ставшие необязательными.
- `packages/connectors/src/*/index.ts` — только если контракт требует правки объявления.

## Вне объёма

- Новые поля конфига и новые коннекторы.
- `scripts/gen-connectors.mjs`, если генерация не требует изменений.
- Валидация в рантайме: она уже работает, дефолты применяются на `parse`. Задача про то,
  что видит **компилятор**, а не про поведение.

## Критерии приёмки

- [ ] КОГДА источник в профиле не указывает поле, у которого в конфиге коннектора есть
      `.default()`, ТО `pnpm typecheck` зелёный, а `pnpm profile:validate` показывает
      значение дефолта применённым.
- [ ] КОГДА источник в профиле не указывает поле БЕЗ дефолта,
      ТО `pnpm typecheck` краснеет, называя поле — обязательное остаётся обязательным.
- [ ] КОГДА в конфиге источника опечатка в имени поля,
      ТО ошибка компиляции сохраняется: свойство, ради которого схема на TypeScript, не
      потеряно.
- [ ] КОГДА `config` вырождается в `unknown` или `never`,
      ТО compile-time стражи в `profiles/schema.ts` краснеют — они не должны ослабнуть
      вместе с типом.
- [ ] КОГДА правка внесена, ТО `profiles/ai-lifehacks.ts` больше не указывает `branch` для
      ленты релизов, а `profiles/_test.ts` проходит валидацию без изменений по смыслу.

## Верификация

```bash
pnpm typecheck
pnpm profile:validate
pnpm verify
```

## Границы

**Не ослабляй тип ради удобства.** `z.record(z.string(), z.unknown())`, `any` или `Partial`
поверх конфига решают задачу и уничтожают единственную причину, по которой профили написаны
на TypeScript, а не на YAML. Стражи в `profiles/schema.ts` существуют ровно против этого —
если после правки они не краснеют на вырожденном конфиге, правка неверна.

**Обязательное поле обязано остаться обязательным.** `minPoints` у HN намеренно объявлен без
дефолта: решение о том, что считается замеченным на Hacker News, принимает тот, кто добавляет
источник. Правка не должна превратить его в опциональное.
