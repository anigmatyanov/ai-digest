# /epic-new

Интервью на 3–4 вопроса, затем декомпозиция. Это самая ценная инвестиция времени владельца: плохая строка в критериях превращается в сотни плохих строк кода.

## Вопросы владельцу

1. **Что станет правдой после мержа** — наблюдаемый результат, одним предложением?
2. **Как это проверить командой?** Если проверки нет — эпик не готов.
3. **Какие файлы это трогает?** Ответ становится `## Объём`.
4. **Что осознанно НЕ делаем** в этот раз?

## Правила нарезки

- **`size` только S или M.** L не бывает: не формулируется одним предложением с одним измеримым результатом — это два эпика с `depends_on`.
- **Один коннектор = один эпик.** Три коннектора — три эпика, запускаемых параллельно.
- **Эпик не пересекает `packages/core ↔ apps/web`.**
- Мелочь (опечатка, однострочник) эпика не заслуживает — она идёт через `quick:`.

## Обязательно проставить

- `serialize` по карте файлов — сверься с реестром в `.claude/rules/backlog.md`. Валидатор поймает пропуск, но лучше не заставлять его.
- `costs_llm: true`, если меняются промпты, модель или число вызовов.
- `touches_output: true`, если меняется то, что увидит читатель — тогда `autonomy` не может быть `auto`.
- `cloud_safe: false`, если нужны живая сеть, реальные секреты или взгляд на превью.
- `autonomy`: `paired` для миграций с бэкфиллом, публикации и смены промпта `compose`.
