# /epic-next

Родительская сессия. Никогда не выполняй шаги 4–6 из worktree — только из главного дерева на `main`.

## 1. Pre-flight

```bash
git rev-parse --abbrev-ref HEAD      # обязан быть main; иначе STOP
git status --short                   # обязано быть пусто; иначе STOP
git pull --ff-only
node scripts/epics.mjs --stale       # exit 2 = есть протухшие claim'ы
```

Протухшие claim'ы сбрасывает только владелец и только после подтверждения. **Никогда не сбрасывай их сам.**

## 2. Выбор

Если `$ARGUMENTS` пуст — бери из `node scripts/epics.mjs --plan`, **не** из `--ready`. Два готовых эпика могут делить serialize-метку; `--plan` это учитывает, `--ready` нет. Назови выбор одной строкой и скажи, почему именно он.

Эпики в секции «not dispatchable — autonomy: paired» **не диспатчатся**. Скажи владельцу, что этот эпик работается интерактивно, и остановись.

## 3. Гейты автономии

- `paired` → STOP. Сообщи и предложи работать интерактивно.
- `plan-gated` с пустым `## План реализации` → запусти **read-only** `Plan`-агента, чтобы он написал план. Закоммить план на `main` (`chore(backlog): E-NNN plan drafted`) и **STOP до одобрения владельцем**.
- `auto` → продолжай.

Перед claim'ом проверь свежесть контракта (`.claude/rules/backlog.md` § Свежесть контракта):

```bash
git log --oneline --since=<created> -- <файлы из ## Объём>
```

Если посылка эпика уехала — STOP, owner-only секции правит владелец.

## 4. Диспатч №1 — провижининг (ожидаемый deny)

Вызови `Agent` с контрактным промптом (ниже). **Хук отклонит этот вызов by design** — это не ошибка. Он создаст worktree, ветку `agent/<slug>`, слот и вернёт инструкцию по retry. Не меняй `description` на повторе.

## 5. Claim-коммит на main — ДО повтора

```bash
# в файле эпика: status: in-progress, claimed_by и branch = agent/<slug>
git add docs/epics/E-NNN-<slug>.md
git commit -m "chore(backlog): claim E-NNN → agent/<slug>"
```

Порядок нагружен смыслом: claim записан до того, как агент начал писать, иначе упавший агент оставит эпик выглядящим свободным.

## 6. Диспатч №2 — повтор

Тот же вызов, но в начало `.prompt` дописан маркер `[managed-worktree: agent/<slug>] …` из текста deny. Больше ничего не меняется.

### Контрактный промпт субагенту

```
Ты реализуешь эпик E-NNN. Связывающий контракт — файл docs/epics/E-NNN-<slug>.md
внутри твоего worktree. Прочитай его целиком, затем .claude/rules/backlog.md
(матрица прав) и .claude/rules/dod.md.

Протокол:
1. Прочитай всё из "## Контекст" в указанном порядке.
2. Запиши пошаговый план в "## План реализации" и закоммить его ДО первого кода.
3. Реализуй строго внутри "## Объём — карта файлов". Работа вне карты филится
   стабом E-NNN<буква> из _template.md со status: draft и discovered_from, а не
   делается инлайн.
4. Прогони каждую команду из "## Верификация"; сохрани вывод для отчёта.
   Сборку доказывай артефактом (pnpm build:proof), а не exit-кодом.
5. Если добавляешь гейт, проверку или тест на починку бага — покажи его КРАСНЫМ
   на дефекте, который он называет, и напиши в отчёте, как это подтверждено.
6. Отмечай чекбоксы ТОЛЬКО по факту проверки. НИКОГДА не редактируй frontmatter,
   текст критериев, ## Объём, ## Границы, ## Верификация.
7. Финальный коммит: "feat(E-NNN): <краткое описание>". pnpm verify зелёный.

Отчёт: что изменилось; вывод верификации; неотмеченные критерии и почему;
как гейт был показан красным; заведённые стабы; предложения правок правил
(НЕ применяй их); rules retrospective тремя строками.
```

## 7. По завершении

Прочитай отчёт, флипни `in-progress → review` на `main` (`chore(backlog): E-NNN → review`), назови порт превью из `.claude/worktrees/.slots` и предложи `/epic-review E-NNN`, затем `/finish-branch agent/<slug>`.

Если субагент умер — эпик остаётся `in-progress`, это увидит `--stale`. Для доработки: флипни `review → in-progress` и **повтори диспатч с тем же `description`** — хук переиспользует живой worktree.
